# Plain shape delivery frontiers survive restart

The lazy change-log checkpoint can trail output a client has already read. Replaying that window at new stream offsets can regress rows and repeat delete/recreate lifecycle effects. Plain Postgres shapes therefore retain their original snapshot fence and registration boundary in the durable catalog before creation is acknowledged, and use a separate per-shape delivery frontier to suppress source effects whose output already landed. The registration boundary also matters for changes-only and empty shapes: a passthrough snapshot gate alone does not exclude history processed before registration. This frontier never advances the engine's input checkpoint or bypasses internal processing.

The log server couples an ordered `Stream-Seq` token to append bytes in its WAL and checkpoint proof. Its committed frontier is exposed with the durable tail. Conditional appends compare the frontier used to build the body under the stream's append lock: pending durability yields backpressure, and a changed frontier requires filtering complete source effects and retrying. That condition also fences an old engine request finishing after a replacement engine has observed HEAD. Tokens identify actual source changes, independent of HTTP requests, read pages and batch sizes.

Payload receipts and a boot-time history scan were considered. They retain identity with bytes but do not alone fence an old append finishing after the scan. Existing producer headers and unconditional sequence conflicts were also insufficient: their metadata could lag durable bytes, and a tentative reservation was not a durability receipt. Moving the input checkpoint ahead of output would lose undelivered work.

Aggregate restore continues to adopt a fresh snapshot and fold. Asynchronous subquery effects need their own ordering model; subquery shapes continue to retire at boot. Library mode retains its existing behavior. The new plain-shape catalog format distinguishes an interrupted modern creation from legacy history with no seed witness; legacy format refuses boot by name rather than inventing a snapshot fence. Interrupted unacknowledged creations can be retired individually. Client resume and deduplication continue to use opaque shape-stream offsets.

The sequenced WAL record requires the new log-server binary. Downgrading over these records is unsupported. The log server advertises the conditional frontier contract explicitly; absence is not interpreted as an empty frontier. WAL mode advertises durable coverage; the existing memory mode advertises volatile coverage and retains its explicit lack of crash durability. This decision addresses ordinary shape delivery; it does not make unsequenced producer counters or asynchronous output universally exactly once.
