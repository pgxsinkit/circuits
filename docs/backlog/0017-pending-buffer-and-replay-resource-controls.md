# 0017 — Pending shapes and dormant replay need resource accounting and bounds

Status: resolved (fixed and qualified 2026-10-03)
Opened: 2026-10-02 · Area: `apps/engine/src/engine/sequencer.rs` (`PendingShape`, replay), `engine/lifecycle.rs` (`resume_dormant`), memory introspection
Reopen trigger: retained pending payload estimates exceeding their configured budget, a spill/drain/retirement regression, or measured RSS, disk growth or latency showing that the remaining unbudgeted state or synchronous spill I/O needs further controls.

Urgency: the pending-payload/replay-work gap is resolved. The remaining limits below need workload evidence; no local OOM or process-wide RSS bound was established.

## Evidence and urgency

Source-confirmed resource gap; no local OOM or production-shaped replay/RSS failure was reproduced. Pending shapes cloned processed table envelopes into a vector while backfill/replay ran; subquery seed nodes and pending outer shapes retained separate weighted-delta vectors. Dormant replay scanned until caught up, with no fixed work endpoint or cross-shape scan admission. Concurrent touches of the same dormant shape already coalesced locally. Shape count and a prolonged seed/replay could multiply retained changes. This affects the native engine, unlike optional DS forks.

First batch `9779fc4` added finite HTTP deadlines and retryable incomplete-body failures. It did not bound pending memory or total replay work. Snapshot-settle record/waiter caps are separate bounds. [0022](0022-subquery-inner-seed-materializes-all-rows.md) now installs inner seed rows in chunks; that removes whole-row seed staging without bounding pending changes, replay work, or query-back candidate rows.

Upstream engine [#17](https://github.com/indexedlabs/electric-circuits/pull/17), merge [44d410ce344b168cb57d60e23dc476634726aae6](https://github.com/indexedlabs/electric-circuits/commit/44d410ce344b168cb57d60e23dc476634726aae6), supplies admission, coalesced scans, pending accounting and recreate outcomes. Its [final review reply](https://github.com/indexedlabs/electric-circuits/pull/17#issuecomment-5534855122) corrects earlier weak/unreproducible test claims. Upstream `reactivation_spans` was declared but never incremented; do not copy a dead metric.

## Design and acceptance

Start with measured memory/work accounting and public-path slow-backfill/slow-replay tests. Decide whether overflow backpressures, spills, or explicitly retires/recreates; an acknowledged batch must land or its shape must be retired through the durable catalog and close-then-delete path. Do not discard deltas while a shape remains registered, or invalidate a transaction because it is large. Keep `(lsn, seq)` exactly-once effect, transaction-end holds and snapshot gates.

If replay gets a fixed end, obtain it from the `BeginShape` acknowledgement where pending buffering starts. Upstream's earlier admission HEAD left a silent gap before buffering; the existing local replay-to-head path does not have that particular gap. Coalesce before taking scan permits, stop retired scans at page boundaries, and measure permit return/queued buffer growth rather than testing a semaphore helper alone.

Add a real growing-log replay with concurrent writes, several same-table wakes behind slow scans, cancellation/retirement, one huge transaction and repeated park/wake cycles. Record peak and post-cycle RSS, bytes scanned and delivery equality. Read caps require [#24](https://github.com/indexedlabs/electric-circuits/pull/24)'s append-budget floor and allowance for values larger than the page target; no engine byte cap exists today. Client retirement/refetch remains [0010](0010-harness-client-does-not-re-subscribe-on-a-retired-stream.md). Complete both validation gates before calling this done.

## Local implementation and boundaries

The 2026-10-03 implementation uses one shared, nonblocking retained-payload memory budget for plain/aggregate pending envelopes and subquery seed/outer delta queues. Overflow spills losslessly to private FIFO files instead of waiting for a memory permit under the owner needed to drain it. The default is 128 MiB; `CIRCUITS_PENDING_MEMORY_BYTES=0` always spills. Queue failures latch an explicit failed attempt. Never-acknowledged creates roll back; dormant retries preserve their original resume position and retention pin. Spill files are process-local scratch, removed on drain/cleanup and swept conservatively at boot for dead processes in the same PID namespace.

Dormant wake admission precedes pending registration, defaults to four concurrent scans, and preserves same-shape coalescing. `BeginShape` returns its raw cursor as the fixed replay endpoint: returning the published cursor alone would miss completed transactions lying after a held transaction's checkpoint pin on the same page. The final page must be trimmed at its original numeric wire boundary, never by reserializing envelopes. Attempt cancellation and identity checks protect retirement against queued registration, activation and cleanup races.

Review found that stopping immediately at an equal resume/endpoint could bypass missing-stream discovery: no GET or append would expose a deleted input, required closed-tail successor, or retained destination. Endpoint integrity and destination checks cover zero-work attempts without extending the scan horizon; confirmed loss retains the existing independent confirmation and durable retirement contract.

A focused production-replay test also reproduced a successor gap when the endpoint segment closed after admission: its current tail exceeded the captured endpoint, so an equality-only check skipped the missing successor and replay returned success. Successor verification must follow observed closure, independently of how many bytes were admitted. Spill accounting includes consumed file prefixes until complete drain; replay pages/bytes count completed GET responses before trimming and exclude HEAD/error traffic.

Maintained RAM/items/spill and replay active/queued/peak/pages/bytes counters are separate from actual RSS. The retained-payload budget excludes source pages, held transactions, transaction output, an oversized decoded weighted-delta group, query-back candidates, deferred distinct-value flips, derived state, codec scratch and allocator slack. Synchronous streaming disk I/O avoids an oversized clone but can occupy the sequencer/registry owner; disk capacity and latency remain operational limits. No transaction becomes invalid because it is large, and no process-wide RSS ceiling is claimed.

## Focused qualification

[Public regressions](../../packages/conformance/src/conformance-pending-replay-bounds.test.ts): six cases passed, followed by a two-case measurement rerun. Two distinct slow plain seeds share a 16 KiB budget; each cycle retained 258 records on disk, with RAM reservations zero after migration and files of 1,109,112 / 1,100,932 bytes. RAM/items/file counters returned to zero after each drain. The subquery case always spills, changes both inner and outer tables during admission, cancels, recreates and compares delivered rows with Postgres.

Actual RSS samples for pending cycles (baseline, held, drained, held, drained) were 43,675,648 / 47,263,744 / 47,456,256 / 49,754,112 / 50,450,432 bytes. Replay samples (baseline, wake, wake) were 43,134,976 / 43,388,928 / 43,491,328 bytes. These are samples at the fixture's states, not a continuously measured process peak or a production soak. RSS did not return to baseline; allocator/source/derived-state costs are outside the retained-payload budget.

Replay admitted one scan with two queued distinct wakes, coalesced repeated touches, cancelled queued and scanning purges, returned all permits and did not resurrect their records. The surviving scan crosses rotation and a transaction split across 64 KiB appends. Growing-log repeated wakes preserve strict same-key stream order across the clipped final page, with no later overwrite masking reversion. The measured wake fixture fetched two pages / 952 response bytes, peak admission one, and ended with active/queued zero. Two zero-range public cases independently confirm missing current/successor history and durable `Dropped`.

[Sequencer tests](../../apps/engine/src/engine/sequencer.rs) cover 1,000-change spilled plain and COUNT activation with bounded appends, the raw-cursor acknowledgement after completed transactions plus a held prefix, mismatched abort identity and cancelled registration after removal. Slow aggregate seeding is not claimed as a public regression: holding its initial POST blocks the sequencer's activation, so that attempted fixture could not let source writes progress. Aggregate spill/drain uses the actual activation unit path, supplemented by the repository's normal aggregate conformance cases.

[Queue tests](../../apps/engine/src/pending_buffer.rs) cover shared reservations, borrowed oversized records without cloning, lossless envelopes/float bits, truncated reads, partial writes, migration failures, poison latching, cleanup, repeated cycles and dead-PID sweeping. [Subquery tests](../../apps/engine/src/subquery.rs) cover borrowed weighted-row encoding, corrupt inner/outer queues, rollback and recreation. [Replay tests](../../apps/engine/src/engine/replay.rs) and [DS framing tests](../../apps/engine/src/ds.rs) cover exact raw boundaries, fixed work under later writes, rotation/held prefixes, zero-range integrity and cancellation. The existing lost-destination test now explicitly qualifies zero-work reactivation while retaining its typed terminal outcome and durable cleanup proof.
